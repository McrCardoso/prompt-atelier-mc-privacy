Privacy Policy

O Prompt Atelier MC foi concebido para dar ao utilizador controlo sobre onde os seus prompts são processados: totalmente offline, num modelo Ollama configurado pelo utilizador ou, opcionalmente, através da API da OpenAI.

Prompt Atelier MC is designed to let users control where their prompts are processed: entirely offline, by a user-configured Ollama model or, optionally, through the OpenAI API.

1. Responsável pela aplicação

1. App controller

O Prompt Atelier MC é um projeto independente desenvolvido e publicado por Marco Cardoso. O programador não opera um servidor próprio para receber prompts, chaves API ou históricos da aplicação.

Prompt Atelier MC is an independent project developed and published by Marco Cardoso. The developer does not operate a server that receives app prompts, API keys or prompt history.

2. Dados tratados pela aplicação

2. Data processed by the app

A aplicação trata apenas os dados que o utilizador introduz ou configura:

The app processes only data entered or configured by the user:

  • objetivo, contexto, audiência, fontes, restrições e restantes campos usados para criar um prompt;
  • prompt gerado, motor selecionado, pontuação e data, guardados no histórico local;
  • preferências da aplicação, modelo escolhido e endereço local do Ollama;
  • chave API da OpenAI, apenas quando introduzida voluntariamente.
  • objective, context, audience, sources, constraints and other fields used to build a prompt;
  • generated prompt, selected engine, score and date, saved in local history;
  • app preferences, selected model and local Ollama address;
  • OpenAI API key, only when voluntarily entered.

A aplicação não pede nome, e-mail, contactos, localização, identificadores publicitários, dados de pagamento, câmara, microfone ou ficheiros pessoais. O utilizador não deve colocar dados pessoais ou confidenciais num prompt sem autorização e necessidade legítima.

The app does not request a name, email, contacts, location, advertising identifiers, payment data, camera, microphone or personal files. Users should not place personal or confidential data in a prompt without permission and a legitimate need.

3. Como cada modo trata os dados

3. How each mode processes data

Offline

O prompt é criado no computador através das regras integradas. Não é efetuado qualquer pedido de rede para gerar o resultado.

The prompt is created on the computer using built-in rules. No network request is made to generate the result.

Ollama

O rascunho é enviado para o endereço Ollama configurado pelo utilizador, que por defeito é localhost. Se o utilizador alterar esse endereço para um servidor remoto, os dados serão tratados por esse servidor e segundo as regras do respetivo operador.

The draft is sent to the user-configured Ollama address, which defaults to localhost. If the user changes it to a remote server, data will be processed by that server under its operator's rules.

OpenAI API

Quando este modo é escolhido, o rascunho do prompt, as instruções de otimização, o modelo selecionado e a chave API são enviados diretamente do computador para a OpenAI através de uma ligação HTTPS. A aplicação define store: false, pelo que não pede à Responses API para manter estado persistente da resposta.

When this mode is selected, the prompt draft, optimisation instructions, selected model and API key are sent directly from the computer to OpenAI over HTTPS. The app sets store: false, so it does not ask the Responses API to keep persistent response state.

A OpenAI pode conservar registos de monitorização de abuso, incluindo conteúdo e metadados, por um período limitado, salvo quando a conta disponha de controlos de retenção diferentes. A utilização está sujeita às políticas da OpenAI e aos controlos de dados da API. O utilizador gere a sua própria conta, chave, faturação e definições da OpenAI.

OpenAI may retain abuse-monitoring logs, including content and metadata, for a limited period unless the account has different retention controls. Use is subject to OpenAI's policies and the API data controls. Users manage their own OpenAI account, key, billing and settings.

4. Armazenamento e conservação local

4. Local storage and retention

As definições e até 100 registos recentes do histórico são guardados em %LOCALAPPDATA%\PromptAtelierMC. O histórico pode conter todos os campos introduzidos e o prompt final. A chave OpenAI é guardada separadamente, cifrada pelo Windows DPAPI para a conta Windows com sessão iniciada.

Settings and up to 100 recent history records are stored in %LOCALAPPDATA%\PromptAtelierMC. History may contain all entered fields and the final prompt. The OpenAI key is stored separately and encrypted by Windows DPAPI for the signed-in Windows account.

Os dados permanecem localmente até o utilizador limpar o histórico, remover a chave ou apagar a pasta da aplicação. Os ficheiros Markdown ou texto exportados ficam no local escolhido pelo utilizador e não são geridos pela aplicação.

Data remains local until the user clears history, removes the key or deletes the app data folder. Exported Markdown or text files remain in the user-selected location and are not managed by the app.

6. Escolhas, acesso e eliminação

6. Choices, access and deletion

  • Escolher Offline para evitar a transmissão do prompt a um fornecedor de IA.
  • Consultar os prompts guardados no ecrã Histórico.
  • Usar Limpar histórico para remover os registos locais.
  • Apagar o conteúdo do campo da chave nas Definições e guardar para remover a chave local.
  • Apagar %LOCALAPPDATA%\PromptAtelierMC para remover os dados locais restantes.
  • Gerir ou eliminar dados mantidos pela OpenAI através da respetiva conta e dos seus canais de privacidade.
  • Select Offline to avoid sending the prompt to an AI provider.
  • View saved prompts on the History screen.
  • Use Clear history to remove local history records.
  • Clear the API key field in Settings and save to remove the local key.
  • Delete %LOCALAPPDATA%\PromptAtelierMC to remove remaining local app data.
  • Manage or delete data held by OpenAI through the relevant account and privacy channels.

7. Segurança e limitações

7. Security and limitations

A chave API é protegida localmente pelo Windows DPAPI e as chamadas à OpenAI utilizam HTTPS. O histórico local não é cifrado pela própria aplicação e herda as proteções da conta, do disco e do dispositivo Windows. Nenhum método é totalmente infalível; o utilizador deve proteger a conta Windows, manter o sistema atualizado e revogar imediatamente uma chave API que suspeite ter sido exposta.

The API key is protected locally by Windows DPAPI and OpenAI calls use HTTPS. Local history is not encrypted by the app itself and inherits the protections of the Windows account, disk and device. No method is completely infallible; users should protect their Windows account, keep the system updated and immediately revoke any API key suspected of exposure.
